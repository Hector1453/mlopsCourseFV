# Diabetes Progression Predicition Project

## Global Project description 
The Diabetes Progression Prediction Project is an end-to-end MLOps pipeline.
Each script is self-contained, independently runnable, and designed to teach one concept
at a time — from raw data ingestion to a containerised, served, and CI-tested model.

**Stack:** Python 3.11 · scikit-learn · MLflow 2.9+ · Pydantic v2 · FastAPI · Docker · GitHub Actions

## Project Goal
The objective of this project is to build a regression model to predict diabetes disease 
progression in patients one year after baseline, based on several numerical features, such as age, 
BMI, and blood pressure, defined by the training dataset.

## Dataset used by the project
The models were trained on the built-in Scikit-learn Diabetes dataset.
It contains the numeric target feature (named `target`) and 10 clinical features:
- `age`: age in years
- `sex`
- `bmi`: body mass index
- `bp`: average blood pressure
- `s1`: tc, total serum cholesterol
- `s2`: ldl, low-density lipoproteins
- `s3`: hdl, high-density lipoproteins
- `s4`: tch, total cholesterol / HDL
- `s5`: ltg, possibly log of serum triglycerides level
- `s6 glu`: blood sugar level
Each of these 10 feature variables were mean centered and scaled by the standard deviation times
the square root of `n_samples` in the source dataset.
Further information can be found on the webpage of the Scikit-learn project:
https://scikit-learn.org/stable/datasets/toy_dataset.html
Three more variables obtained by data engineering were used in the training 
(`bmi_age_interaction`, `bp_bmi_interaction` and `s1_s2_ratio`). 
See `feature_engineering.py` script for more details.

## Data pipeline

Run from the project root. Each script depends on the output of the previous one.
Previous data files with the name of the output are overwritten.

```bash
python src/data/data_extraction.py      # → data/raw/diabetes_dataset.csv
python src/data/data_validation.py      # validates data
python src/data/data_cleaning.py        # → data/processed/train_v1.csv
python src/data/feature_engineering.py  # → data/processed/train_features_v1.csv
```

| Script | Input | Output |
|---|---|---|
| `data_extraction.py` | sklearn API | `data/raw/diabetes_dataset.csv` |
| `data_validation.py` | `data/raw/diabetes_dataset.csv` | console summary |
| `data_cleaning.py` | `data/raw/diabetes_dataset.csv` | `data/processed/train_v1.csv` |
| `feature_engineering.py` | `data/processed/train_v1.csv` | `data/processed/train_features_v1.csv` |

## Model Training

```bash
python src/models/train.py
```

Trains a `LinearRegression`, a `RandomForestRegressor(n_estimators=100)` and a 
`GradientBoostingRegressor` on `train_features_v1.csv`. Each model is logged as a separate run in the
`diabetes` experiment with metrics `rmse`, `mae`, `r2`.

---

## Model Registry

```bash
python src/models/register_model.py
```

Queries all finished runs, picks the one with the lowest RMSE, and registers it as
`diabetes-model` in the MLflow Model Registry.

**Requires:** **Model Training** to have been run at least once.

---

## Model Evaluation (`champion` selection)

```bash
python src/models/evaluate_model.py
```

Loads the latest version of `diabetes-model`, runs `mlflow.evaluate()` on
the held-out test set, and checks the threshold:

| Metric | Threshold |
|---|---|
| RMSE | < 60 |

If the threshold is met, the alias `champion` is assigned. You can then load the
production-ready model anywhere with:

```python
import mlflow
model = mlflow.pyfunc.load_model("models:/diabetes-model@champion")
```

**Requires:** **Model Registry** to have been run at least once.

## Running the API

The API serves predictions from whichever model version holds the `champion` alias.
Run **Model Training**, **Registry** and **Evaluation** before starting the server.

### Local

```bash
uvicorn src.api.main:app --reload
# Docs: http://localhost:8000/docs
```

### Endpoints: `health`, `model-info` and `predict`

| Method | Path | Description |
|---|---|---|
| `GET` | `/health` | Liveness check |
| `GET` | `/model-info` | Name, version, alias, run\_id of the loaded model |
| `POST` | `/predict` | Returns `{"prediction": float, "model_version": str}` |

The status of every endpoint can be checked in the Docs interface (http://localhost:8000/docs)
and in the shell.
The most common messages are:

| Method | Path | Code | Meaning |
|---|---|---|---|---|
| `GET` | `/health` | 200 | OK: service alive and model available |
| `GET` | `/model-info` | 200 | OK: model correctly loaded and metadata returned. |
| `GET` | `/model-info` | 503 | ERROR: model not loaded. |
| `POST` | `/predict` | 200 | OK: valid input, prediction returned |
| `POST` | `/predict` | 422 | ERROR: validation error (invalid data type, absent or erroneous features) |
| `POST` | `/predict` | 500 | ERROR: prediction error |

Predictions for new values can be requested in the Docs interface (http://localhost:8000/docs)
or throug the shell (`curl` command), adapting the values to the following example request:

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
    "age": 0.038, "sex": 0.038, "bmi": 0.050, "bp": 0.061, "s1": 0.021, 
    "s2": -0.044, "s3": -0.034, "s4": -0.043, "s5": -0.002, "s6": 0.019
  }'
```

``` windows
curl.exe -X POST http://localhost:8000/predict -H "Content-Type: application/json" -d '{ \"age\": 0.038, \"sex\": 0.038, \"bmi\": 0.050, \"bp\": 0.061, \"s1\": 0.021, \"s2\": -0.044, \"s3\": -0.034, \"s4\": -0.043, \"s5\": -0.002, \"s6\": 0.019 }'
```

(Remember that data values should be mean centered and scaled as in the source dataset)

## CI/CD

Every push to `master` or `main`triggers `.github/workflows/ci.yml`, which runs the full
pipeline in order:

```
data_extraction → data_validation → data_cleaning → feature_engineering
  → train → register_model → evaluate_model
```

If `evaluate_model.py` exits with code 1 (quality gate not met), the workflow fails
and no broken model reaches the registry.
